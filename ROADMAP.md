# Roadmap

What PR Constellation does today, and where it goes next. Order is intent, not a schedule.

## Now

- [x] **Understand how changes connect:** review a pull request as Review Stacks and linked file/section nodes instead of an isolated file list.
- [x] **Reduce review noise:** choose the detail you need with 0.1x, 1x, and 10x density.
- [x] **Review in context:** each node explains why the change matters; inspect the diff and PR conversation, then draft review comments without leaving the review.
- [x] **See what needs attention:** the GitHub inbox is ranked so priority pull requests surface first.

## Next

- [ ] **Ask questions about a pull request:** chat with the analysis before leaving a comment.
- [ ] **Keep reviews time-bound:** show a review clock for each Review Stack to help you stay focused and finish reviews faster.
- [ ] **Get notified about inbox changes:** send updates through the browser or Slack.
- [ ] **See the full code behind a change:** connect a review to a local checkout of the project to view the complete diff and surrounding source.

## Later

- [ ] **Explain the wider codebase:** connect an existing repository wiki to give reviews more project context.
- [ ] **Review inside your editor:** add a VS Code and Cursor extension.
- [ ] **Track review progress:** mark each file or section as read in the Review Tree.
